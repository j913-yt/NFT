# 答辩提炼要点

## 论文主题

题目：NFT数字藏品交易平台的设计与实现。

目标：围绕数字藏品的确权、展示、交易和资产管理，构建一个前后端分离、链上链下协同的 NFT 交易平台。

## 需要在 PPT 中重点讲的功能

1. 钱包签名登录：通过钱包地址获取 nonce，用户签名后由后端校验并签发 JWT。
2. 数字藏品创建：填写名称、描述、分类、价格、版税比例，上传图片/音频/视频等资源。
3. IPFS 存储：媒体文件和 metadata 上传到 IPFS/Pinata，生成可追溯资源地址。
4. 智能合约铸造：前端调用合约，钱包确认交易，生成 TokenID 并完成链上确权。
5. 市场浏览与详情：展示藏品封面、名称、价格、分类、合约地址、TokenID、TokenURI、版税等信息。
6. NFT 交易：买家通过钱包确认链上购买，交易成功后后端保存订单并更新所有者。
7. 上架与下架：持有者可上架、修改价格、下架，链上状态完成后同步链下价格和交易状态。
8. 个人中心：展示钱包地址、资料、持有藏品、买入记录、卖出记录和交易哈希。
9. 通知提醒：前端已有通知中心组件，用于交易和状态变化反馈。

## 技术结构

- 前端：Next.js、React、RainbowKit、wagmi、ethers.js、Tailwind CSS。
- 后端：Go、Gorilla Mux、GORM、MySQL、JWT。
- 合约：Solidity、ERC-721、EIP-2981、OpenZeppelin。
- 存储：IPFS/Pinata 保存媒体文件和 metadata。
- 核心原则：链上负责确权、铸造、上架、下架、购买和版税；链下负责页面展示、用户资料、NFT 镜像数据和订单查询。

## 数据设计

核心实体为 User、NFT、Order：

- User：钱包地址、用户名、头像、nonce、创建时间。
- NFT：合约地址、TokenID、名称、描述、媒体地址、TokenURI、分类、拥有者、价格、版税。
- Order：NFTID、买家、卖家、成交价格、交易哈希、状态、创建时间。

## 测试结论

论文测试覆盖用户登录、数字藏品创建、展示与详情、上架下架、购买订单、个人中心。结论为主要流程可正常完成，链上交易与链下数据同步正常，能满足数字藏品创建、展示、交易和管理的基本需求。

## 答辩表达重点

- 不要把时间花在大量背景介绍上，背景只讲“为什么需要链上确权和交易追溯”。
- 5-7 分钟内重点讲系统功能闭环：登录 -> 创建 -> IPFS -> 铸造 -> 展示 -> 上架/购买 -> 订单同步 -> 个人中心。
- 技术部分服务于功能：说明每层解决什么问题，而不是泛讲技术概念。
