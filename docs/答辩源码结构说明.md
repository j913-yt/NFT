本文档基于当前仓库实际文件整理，适合在答辩时向老师说明“项目有哪些目录、每个目录负责什么、关键文件做什么”。

## 1. 根目录总览

### 1.1 业务相关目录

| 路径 | 说明 |

| `backend/` | Go 后端服务，负责登录鉴权、IPFS 上传、NFT 链下记录、订单记录和头像上传。 |

## 2. `backend/` 后端目录

后端采用典型分层结构：

- `cmd` 放启动入口。
- `router` 负责组装路由。
- `handler` 处理 HTTP 请求。
- `service` 处理业务逻辑。
- `repository` 管数据库初始化。
- `model` 定义数据表结构。
- `middleware` 处理鉴权、跨域、限流。
- `util` 放通用工具。

### 2.1 `backend/cmd/server/`

| 文件 | 说明 |
| --- | --- |
| `backend/cmd/server/main.go` | 后端启动入口，创建路由、挂载跨域中间件并监听 `:8080` 端口。 |

### 2.2 `backend/internal/config/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/config/config.go` | 读取 `.env` 和环境变量，整理 JWT、MySQL、Pinata、IPFS 网关、当前合约地址等配置。 |

### 2.3 `backend/internal/router/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/router/router.go` | 统一注册 `/api/v1` 路由，创建认证、NFT、订单、上传、IPFS 相关 handler 和 service。 |

### 2.4 `backend/internal/model/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/model/models.go` | 定义 `User`、`NFT`、`Order` 三张核心数据表，是数据库结构的来源。 |

### 2.5 `backend/internal/repository/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/repository/db.go` | 初始化 MySQL、自动建库建表、执行 GORM 迁移，并补齐历史记录里的价格字段。 |

### 2.6 `backend/internal/middleware/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/middleware/auth.go` | JWT 鉴权中间件，从请求头解析 token，并把当前用户 ID 写入上下文。 |
| `backend/internal/middleware/cors.go` | 处理开发环境跨域访问，允许前端从浏览器请求后端 API。 |
| `backend/internal/middleware/ratelimit.go` | 内存限流中间件，限制上传等接口在单位时间内的访问次数。 |

### 2.7 `backend/internal/handler/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/handler/auth.go` | 处理钱包登录相关接口，包括获取 nonce、钱包签名登录、更新个人资料。 |
| `backend/internal/handler/ipfs.go` | 处理 NFT 主媒体、封面、元数据上传到 IPFS 的接口。 |
| `backend/internal/handler/nft.go` | 处理 NFT 列表、详情、创建链下记录、更新上架价格等接口。 |
| `backend/internal/handler/order.go` | 处理订单创建、已售列表、已购列表、NFT 交易历史等接口。 |
| `backend/internal/handler/upload.go` | 处理头像上传接口，把头像保存到本地静态目录。 |

### 2.8 `backend/internal/service/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/service/auth.go` | 实现钱包地址规范化、nonce 生成、签名验签、JWT 签发和资料更新逻辑。 |
| `backend/internal/service/ipfs.go` | 封装 Pinata/IPFS 上传能力，支持上传文件和上传元数据 JSON。 |
| `backend/internal/service/nft.go` | 实现 NFT 链下镜像数据的列表查询、详情查询、创建和上架状态更新。 |
| `backend/internal/service/order.go` | 实现订单落库、购买后更新 NFT 拥有者、查询买卖双方交易记录。 |

### 2.9 `backend/internal/util/`

| 文件 | 说明 |
| --- | --- |
| `backend/internal/util/price.go` | 负责 ETH 与 wei 的相互转换，保证链上价格使用精确整数。 |
| `backend/internal/util/upload.go` | 负责头像、NFT 媒体、封面文件的 MIME 类型白名单校验。 |

### 2.10 `backend/scripts/`

| 文件 | 说明 |
| --- | --- |
| `backend/scripts/reset_contract_data.sql` | 合约重部署后重置链下 `nfts` 与 `orders` 数据的 SQL 脚本，默认保留用户表。 |

## 3. `contracts/` 智能合约目录

### 3.1 文件说明

| 文件 | 说明 |
| --- | --- |
| `contracts/NFTCollection.sol` | 项目的核心 ERC-721 合约，支持铸造、上架、下架、购买和 EIP-2981 版税。 |

### 3.2 合约里最重要的能力

| 能力 | 说明 |
| --- | --- |
| `safeMint` | 只铸造 NFT，不自动上架。 |
| `mintAndList` | 一笔交易中完成铸造并立即上架。 |
| `listToken` | 把已有 NFT 按固定价格重新上架。 |
| `cancelListing` | 下架 NFT，保留所有权。 |
| `buy` | 买家用链原生代币购买 NFT，并自动处理版税和卖家收入。 |
| `getListing` | 查询链上上架状态。 |
| `getRoyaltyInfo` | 查询某个 NFT 在指定售价下的版税金额。 |

## 5. `frontend/` 前端目录

前端使用 `Next.js + React + RainbowKit + wagmi + ethers`。职责是连接钱包、展示页面、上传文件、调用后端接口，并在需要时直接发起链上交易。

### 5.1 前端根文件

| 文件 | 说明 |
| --- | --- |
| `frontend/.env.local` | 前端本地运行配置文件，通常保存 API 地址、合约地址、RPC 地址等环境变量。 |
| `frontend/.env.local.demo` | 前端环境变量示例文件，说明本项目需要配置哪些公开环境变量。 |
| `frontend/package.json` | 前端依赖和脚本配置，定义 `dev`、`build`、`start`、`lint`。 |
| `frontend/package-lock.json` | npm 锁定文件，固定依赖版本，保证团队环境一致。 |

### 5.2 `frontend/app/`

## 6. 适合答辩时的整体表述

如果老师从源码结构角度提问，这个项目可以概括成一句话：

> `frontend` 负责页面、钱包连接和链上交互，`backend` 负责登录、上传和链下数据管理，`contracts` 负责 NFT 的真实链上资产逻辑，`docs` 负责系统流程说明，其他目录主要是开发过程记录和 IDE 配置。
